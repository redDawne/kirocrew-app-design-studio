For teams who have typed "retry: 3" and felt bad about it

A flaky test is a bug you only get to see once. Tapedeck keeps the recording.

Our CLI records each CI test run down to the clock, the network and the order threads woke up. When a run fails, you replay that exact run on your machine, as often as you like, with a debugger attached.

The method, in three moves

tapedeck record -- go test ./...

Record in CI

One static binary in front of your test command. It intercepts syscalls, not your code, so nothing in the repo changes.

tapedeck pull gh:org/repo#4412

Pull the failed tape

Green runs are thrown away. Red and retried runs upload, typically 20-60 MB each.

tapedeck replay --break ledger/client.go:118

Replay until you understand it

Time, randomness and every network response come back exactly as CI saw them. The test fails the same way on run one and on run two hundred, which is the whole point.
